This is the Go API the website, the MCP server and the phone gateway talk to. Each endpoint has its own page with what
it does, its parameters and body, its responses with examples, code samples (cURL, JavaScript, Go, Python, Java, C#)
and a **playground**: fill it in and press **Send** to call your own TalNex API.

The pages are generated from `backend/api/openapi.yaml`. A Go test fails if a route in
`backend/internal/http/server.go` is missing from that file, so the reference cannot fall behind the code.

## Before you press Send

<Steps>
<Step>
**Start TalNex** (`docker compose up -d` in the repository root). The playground calls `http://localhost:8080` by
default; change the server address at the top of any playground to use another stack. That address must also be listed
in `TALNEX_DOCS_API_ORIGINS`, because requests go through the website (so the API needs no CORS change).
</Step>
<Step>
**Get a token.** Every `/v1` route needs `Authorization: Bearer <token>`, a short-lived token signed with the API's
`AUTH_SECRET` and naming an email and a role. For local testing, this site can make one for you:
</Step>

## What the routes have in common

- **Results are private.** Someone else's event, project or candidate answers `404`, exactly like one that does not
  exist.
- **Roles.** Organizer routes refuse a recruiter token and the other way round, with `403`.
- **Errors** are JSON with one field, `error`, in plain words.
- **Money.** Starting checks (`run`, `confirm`, `rerun`, a resume upload) spends money. The MCP server puts these
  behind `confirm: true`; the API itself does not, so the playground starts them for real.
- **Live events** (`GET /v1/live/{kind}/{id}`) are a Server-Sent Events stream. The playground cannot show a stream;
  use `curl -N` or the MCP server's `watch_live`.

## Groups

| Group | What is in it |
|---|---|
| Account | Who the token signs in as |
| Events | Organizer: hackathon events, criteria, starting checks |
| Projects | Organizer: the teams of an event |
| Proof | Organizer: proof cards, the event overview, who built each feature best |
| Candidates | Recruiter: roles, candidates, resumes, confirmation, progress, reports |
| Walkthroughs | Ask how a feature works, or ask TalNex about a card or a report |
| Live | The live event stream |
| SMS gateway | The team phone's route for one-time codes |
| Health | Liveness and readiness, no sign-in |
| Dev | Only with `ENABLE_DEV_ENDPOINTS=true` |
